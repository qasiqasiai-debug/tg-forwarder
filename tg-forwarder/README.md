# TG Forwarder — пересылка публикаций из 54 каналов в один чат

Python 3.10+ · Telethon (MTProto, чтение каналов) · aiogram 3 (управление) · SQLite.

## Как это устроено

```
 54 каналов ──► Telethon-клиент (ваш аккаунт) ──► очередь в SQLite ──► целевой чат
                     ▲   события + страховочный опрос        │ дедупликация, порядок,
                     │                                        │ ретраи, FloodWait
 Вы ◄──► aiogram-бот (/start, /status, …) ◄───────────────────┘
```

- **Bot API не умеет читать чужие каналы**, поэтому каналы читает *авторизованный аккаунт* (Telethon, `SESSION_STRING`). Он же отправляет посты в целевой чат — **этот аккаунт должен состоять в целевом чате и иметь право писать**.
- Бот (токен от @BotFather) нужен только для управления и уведомлений; управлять им может только `OWNER_ID`.
- Новые посты ловятся мгновенно (события MTProto). Раз в `POLL_INTERVAL` сек идёт страховочный опрос, а после перезапуска/обрыва бот **догоняет пропущенное** (не старше `CATCHUP_MAX_AGE_HOURS`).
- Очередь хранится в SQLite: если целевой чат недоступен или сервер перезагрузился, публикации не теряются и уходят позже. Порядок сохраняется (по дате поста). Повторов нет (`forwarded` + уникальный ключ очереди).
- Два режима (`/mode`): `forward` — обычная пересылка (сохраняет всё как есть, виден источник; **по умолчанию**) и `copy` — копия без «Переслано из». Если канал запретил пересылку, бот сам скачает и перезальёт медиа.
- Альбомы пересылаются целиком как одна публикация.

> ⚠️ Используйте для этого **отдельный аккаунт** (желательно не основной). Автоматизация пользовательского аккаунта допустима при умеренной нагрузке, но массовое вступление в каналы и спам могут привести к ограничениям. Не запускайте две копии с одной `SESSION_STRING` — Telegram отзовёт сессию.

## 1. Получение API_ID и API_HASH

1. Откройте https://my.telegram.org и войдите по номеру телефона **того аккаунта, который будет читать каналы**.
2. **API development tools** → создайте приложение (любое название, платформа Other).
3. Скопируйте **App api_id** → `API_ID` и **App api_hash** → `API_HASH`.

## 2. Бот, OWNER_ID и SESSION_STRING

1. **BOT_TOKEN**: в Telegram напишите @BotFather → `/newbot` → скопируйте токен.
2. **OWNER_ID**: напишите @userinfobot — он пришлёт ваш числовой id.
3. Откройте своего бота и нажмите **Start** (иначе он не сможет вам писать).
4. **SESSION_STRING** (на сервере или локально):
   ```bash
   python -m scripts.gen_session
   ```
   Введите API_ID, API_HASH, номер телефона, код из Telegram (и пароль 2FA). Скрипт выведет длинную строку — вставьте её в `.env`. Она равна доступу к аккаунту: никому не показывайте.

## 3. Запуск на VPS (Ubuntu/Debian)

```bash
sudo apt update && sudo apt install -y python3 python3-venv git
sudo useradd -r -m -s /bin/bash tgbot
sudo mkdir -p /opt/tg-forwarder && sudo chown tgbot: /opt/tg-forwarder
sudo -iu tgbot
cd /opt/tg-forwarder
# загрузите сюда файлы проекта (scp / git clone / unzip), затем:
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env && chmod 600 .env && nano .env     # заполните значения
.venv/bin/python -m scripts.gen_session                 # если SESSION_STRING ещё нет
.venv/bin/python -m app                                  # пробный запуск, Ctrl+C для остановки
```

При запуске бот пришлёт вам панель: статус, каналы `N/54`, число пересылок, время последней успешной пересылки и кнопки.

## 4. Автозапуск после перезагрузки (systemd)

```bash
sudo cp /opt/tg-forwarder/deploy/tg-forwarder.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tg-forwarder
systemctl status tg-forwarder          # состояние
journalctl -u tg-forwarder -f          # логи (также в data/logs/bot.log)
```

`Restart=always` перезапускает процесс при падении, `enable` — поднимает его после ребута. При ошибке конфигурации/отозванной сессии (код 78) цикл перезапусков не запускается — исправьте `.env` и выполните `sudo systemctl restart tg-forwarder`.

**Вариант с Docker:** `cp .env.example .env`, заполните, затем `docker compose up -d --build` (`restart: unless-stopped` поднимет контейнер после ребута; данные в `./data`).

## 5. Подключение 54 каналов

**Рекомендуемый порядок:**

1. Подпишите аккаунт-«читатель» на все каналы (вручную в приложении Telegram — быстрее и безопаснее для лимитов; для приватных каналов нужны инвайт-ссылки).
2. Создайте целевой чат (группу или канал), добавьте туда аккаунт-«читатель» с правом писать. Если хотите выполнить `/setchat` прямо в группе — добавьте туда и бота.
3. Подготовьте файл `channels.txt` — по одному каналу в строке (формы: `@name`, `https://t.me/name`, `https://t.me/+инвайт`, `-100…`; `#` — комментарий). Образец: `channels.txt.example`.
4. В боте:
   - `/setchat @имя_чата` (или `/setchat` внутри нужной группы; `me` — для теста в «Избранное»),
   - отправьте боту файл `channels.txt` **или** положите его на сервер рядом с проектом и выполните `/import`,
   - `/channels` — проверьте список: ✅ подключён, ⚠️ с ошибкой (причина указана).
5. `/status` должен показать `Каналов подключено: 54/54` и состояние «✅ Работает».

Если аккаунт ещё не подписан на публичный канал, бот вступит в него сам, делая паузу `JOIN_DELAY` между вступлениями. При FloodWait добавление остановится с понятным сообщением — повторите `/import` позже (уже добавленные пропускаются). История канала при добавлении **не** пересылается — только новые посты.

## Команды

| Команда | Действие |
|---|---|
| `/start` | панель: статус, `N/54`, счётчик пересылок, время последней пересылки, кнопки |
| `/status` | то же, обновлённое |
| `/channels` | список каналов со статусами |
| `/addchannel` | `/addchannel @a @b …` или без аргументов — бот ждёт список / .txt |
| `/removechannel` | по номеру из `/channels`, `@username`, ссылке или id |
| `/setchat` | целевой чат: `@name` / ссылка / id / без аргументов в группе |
| `/stats` | всего, за 24ч и 7 дней, очередь, ошибки, топ каналов |
| `/pause` | остановить отправку (посты продолжают копиться в очереди) |
| `/resume` | возобновить; `/resume clear` — сначала очистить накопленную очередь |
| `/mode` | `forward` или `copy` |
| `/import` | загрузить каналы из `channels.txt` на сервере |

## Переменные окружения

См. `.env.example`. Секреты (`API_ID`, `API_HASH`, `BOT_TOKEN`, `SESSION_STRING`) лежат только в `.env` (права 600, в `.gitignore`) и не пишутся в логи. Хранятся только id каналов, названия и служебная история пересылок — персональные данные подписчиков не сохраняются.

## Надёжность

- Автопереподключение Telethon + собственный watchdog; после восстановления связи — догон пропущенного и уведомление владельцу.
- FloodWait: ожидание ровно столько, сколько требует Telegram; пауза `SEND_INTERVAL` между отправками.
- Недоступный целевой чат или сеть: публикации остаются в очереди без лимита попыток; владельцу приходит уведомление (не чаще раза в 30 минут).
- Удалённый/недоступный источник пропускается; прочие ошибки — до 8 попыток, затем пропуск с уведомлением.
- Фоновые задачи перезапускаются супервизором; процесс — systemd/Docker.

## Решение проблем

- **«Каналов 0/54», ⚠️ «аккаунт не подписан»** — подпишите аккаунт на канал и перезапустите сервис (статусы каналов перепроверяются при старте).
- **Бот молчит** — вы нажали Start у бота? Верен ли `OWNER_ID`? Бот игнорирует всех, кроме владельца.
- **Не удаётся `/setchat`** — аккаунт-«читатель» должен быть участником чата и иметь право писать.
- **Сессия отозвана / AuthKeyDuplicated** — запущено две копии или вход с другого IP. Остановите лишнее и выпустите новую `SESSION_STRING`.
